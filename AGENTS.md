# Инструкции для агентов: React

Прочитайте [продукт](docs/product.md), [реализацию](docs/implementation.md) и [проверки](docs/development.md). В общей рабочей папке также действуют требования родительского AGENTS.md.

- React отвечает за представление и взаимодействие. Новые обязательные бизнес-проверки реализуются в соответствующем сервисе Corelia.
- Все команды пользователя направлять через `/api/core/v1`. Не добавлять прямых записей в DataSpace/BPM или зависимостей от архивного BFF.
- Преобразование контрактов держать в src/api, представление — в pages/components, общие формы видов — в features/documents. Не считать формы автоматически генерируемыми из каталога.
- Различать ID документа, номер снимка, ID файла и ID задачи. Историческая карточка доступна только для просмотра; её workflow относится к текущему процессу.
- PATCH передаёт expectedVersion, changeToken и requestId. Не обходить конфликт 409 слепым повтором с новым токеном. Повтор потерянного ответа должен сохранять исходную команду.
- Учитывать ограничения текущего повтора файлов: pendingUpload живёт только в форме создания, замена и удаление генерируют новый requestId на каждый вызов.
- Не использовать видимость кнопки как доказательство права; ядро проверяет состояние и назначенного исполнителя.
- Не размещать секреты в VITE-переменных, исходниках, документации или логах. localStorage сейчас содержит сессию, включая токены; не описывать это как серверную cookie-сессию.
- Перед изменениями проверить git status, сохранить пользовательские правки. При изменении поведения обновить профильную документацию.
- Для проверки TypeScript использовать npm run lint; для изменения сборки или приложения — npm run build и нужные ручные сценарии. Сборка не доказывает совместимость рабочего стенда.
