# Продукт: рабочее место документов

Клиент даёт пользователю доступ к документам СберНПФ и задачам их обработки через Corelia. Это интерфейс системы документооборота; хранение файлов, правила изменения карточек и исполнение процессов находятся за API.

## Пользователи и виды

Оператор создаёт и обрабатывает документы; согласующий участвует в процессе ПДС; владелец приложения обладает правами в соответствии с ядром и платформой. Роль сама по себе не гарантирует возможность редактирования: учитываются состояние документа и исполнитель задачи.

| Вид | Поля формы | Сценарий |
| --- | --- | --- |
| Договор ПДС / PDS_CONTRACT | Дата, номер договора, СНИЛС | Создание, обработка, согласование, доработка или отклонение |
| КИД ОПС / KID_OPS | Дата, номер договора, год подписания, ФИО, СНИЛС | Создание с первым файлом, работа оператора, отправка на хранение |

КИД ОПС требует всех полей, кроме отчества. Номер имеет формат ОПС-123-4567-1234567, год — четыре цифры, СНИЛС — 123-456-789 00. Маска СНИЛС не проверяет подлинность номера. Обязательные проверки повторяются ядром.

## Экраны и действия

- Вход и завершение сессии.
- Главная страница с доступом к документам и задачам.
- Реестр с фильтрами по виду, строке поиска, статусу и датам.
- Пошаговая форма создания, выбор файлов и предпросмотр.
- Карточка с реквизитами, файлами, исполнителем, текущим процессом и доступными действиями.
- Очереди «Мои» и доступных задач, взятие в работу и выполнение действия.
- История реквизитов, просмотр выбранной версии и предыдущих версий файла.

Редактирование в карточке доступно для текущей версии в IN_WORK, когда текущий пользователь — назначенный оператор. Исторический просмотр отключает редактирование и процессные действия. КИД ОПС в STORED остаётся доступен для чтения; состав и реквизиты больше не меняются через обычный сценарий.

## Версии и файлы

Новая версия реквизитов не означает новый процесс. Номер версии документа и номер версии содержимого файла независимы. Закрытый снимок сохраняет свой состав файлов; статус и workflow исторической карточки относятся к текущему общему процессу.

Предпросмотр реализован для PDF, DOCX и XLSX. Скачивание получает файл через Corelia с пользовательским токеном. Предпросмотр не является редактором документов и не гарантирует идентичность отображения настольному Office.

При сбое дополнительных вложений после успешного создания форма предлагает повторить загрузку в ту же карточку или открыть документ. Это состояние хранится в памяти формы и теряется при перезагрузке или уходе со страницы.

## Границы текущего интерфейса

Поддержка нового вида требует формы, типов и адаптации API наряду с изменениями ядра. Каталог видов сам по себе не создаёт новый UI. Автоматического объединения пользовательских правок при конфликте 409 нет. Действия процесса берутся из ответа ядра; клиент не выбирает произвольный новый status.

## Переход к capabilities

Карточка запрашивает `/documents/{type}/{id}/capabilities`. Редактирование и управление файлами определяются ответом ядра; клиент больше не сопоставляет роль исполнителя с document_operator. Пока ответ загружается или выбран исторический снимок, изменения недоступны. Обязательные проверки повторяются при выполнении команды. Формы, типы реквизитов и описание процессов пока остаются специализированными: это ещё не generic React.
