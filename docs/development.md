# Разработка и проверка React

Все команды — из корня sber-npf-react.

```bash
npm ci
npm run dev
```

Vite настроен на порт 7171. Скрипт dev использует --host 0.0.0.0; при занятом порте ориентируйтесь на фактический адрес, напечатанный Vite. Gateway по умолчанию — http://localhost:7170, другой адрес задаётся VITE_API_BASE_URL. Секреты в VITE-переменные не помещать: они доступны браузеру.

```bash
npm run lint
npm run build
npm run preview
```

lint — проверка TypeScript, а не ESLint. build компилирует TypeScript и собирает Vite в dist. Отдельного автоматического test-скрипта нет. Preview показывает сборку; production-хостинг требует настройки возврата index.html для SPA-маршрутов и совместимого CORS/API.

## Ручные сценарии по изменяемой области

| Область | Проверка |
| --- | --- |
| Сессия | Вход, выход, переход на защищённый URL, истечение токена и обновление |
| Реестр | Оба вида, фильтры, пустая выдача, ошибка API |
| Создание | ПДС; КИД ОПС с обязательным первым файлом; ошибка дополнительных файлов и повтор в той же карточке |
| Реквизиты | Назначенный оператор, запрет чужому исполнителю, корректные/неверные поля, конфликт 409 |
| Версии | Новая версия после правки, прежний состав файлов, блокировка исторического редактирования |
| Вложения | PDF/DOCX/XLSX, скачать, заменить, удалить, история, ошибка сети |
| Задачи | MY/AVAILABLE, взятие, действия из API, обновление состояния документа |
| Хранение КИД ОПС | STORED и отсутствие редактирования |

Использовать согласованный тестовый контур для действий, создающих данные. Не объявлять успешную сборку подтверждением реального BPM или permissions.

## Диагностика

Проверить итоговый URL в Network, статус и message ошибки. Для 401 учитывать, что бинарное скачивание не использует общий refresh; для 409 — актуальность снимка и ключа команды; для 504 — длительность и логи соответствующего сервиса Corelia. Не выводить токены и содержимое пользовательских файлов в диагностические логи.
