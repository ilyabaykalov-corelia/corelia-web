# Реализация Corelia Web

Продуктовый пакет называется `corelia-web`. Рабочий Git-каталог пока сохраняет имя `sber-npf-react`, чтобы не менять существующие пути сборки и удалённый репозиторий. UI не содержит идентификаторов видов, реквизитов, ролей или статусов СберНПФ.

## Каталог и формы

`GET /api/core/v1/document-types` поставляет schema/ui, статусы и политику вложений. `DocumentType` описывает этот контракт; `DocumentRecord.attributes` сохраняет произвольные скалярные реквизиты без списка полей в API-клиенте. При недоступном каталоге встроенный вид по умолчанию не подставляется.

`DocumentFields` строит поля в порядке ui.fields: строки, даты, числа, целые, boolean и enum. Проверки длины считают Unicode code points; date проверяет календарную дату. Клиентские проверки служат удобству; нормализация и обязательная валидация остаются в document-service. Маски специфичных реквизитов не зашиты в продукт. Ограниченный профиль схем описан в Corelia configuration.md.

Создание использует metadata initialAttachmentRequired: первый файл передаётся вместе с командой, остальные после создания. UUID создания и пакет дополнительных файлов сохраняются в состоянии формы для повтора. После перезагрузки страницы это состояние теряется. Политика enabled/maxCount управляет выбором вложений.

Карточка отображает ui.fields и универсальный attributes, неизвестные исторические реквизиты доступны при отсутствии определения вида. PATCH сохраняет expectedVersion/changeToken/requestId формы; конфликт 409 не обходится. После записи клиент перечитывает документ; ошибка чтения не означает отката записи. Исторические снимки доступны только для чтения.

## Реестр и процессы

Реестр получает серверные страницы, поиск и фильтры. Для выбранного вида колонки берутся из ui.columns, поисковые подсказки из searchFields, дата из dateField, статусы из каталога. В общем списке реквизиты каждого документа показываются по его определению. Сортировка по ui.sortFields применяется только к текущей странице и явно так подписана. Числа сравниваются численно.

Главная показывает реальные документы; демонстрационные задачи и счётчики конкретных статусов удалены. Боковое меню показывает каталог, в том числе виды без поля даты. Индекс годов строится только по загруженным документам и настроенному dateField; это не полный серверный справочник лет.

Действия карточки приходят из workflow.availableActions и выполняются по коду через `/documents/{type}/{id}/actions/{action}`. Клиент не формирует процессный результат из статуса. Представление процесса показывает текущее состояние и задачу из API, без выдуманного маршрута согласования.

## Доступ и файлы

Карточка получает capabilities от ядра, повторно загружая их при изменении текущей версии/состояния. Пока они не получены и при выборе истории, изменения закрыты. Сервер повторяет проверки при каждой команде.

PDF/DOCX/XLSX предпросмотр, загрузка, замена, удаление и история файлов сохранены. replace/delete пока создают новый requestId при каждом ручном вызове. Скачивание отдельным fetch не использует общий refresh JSON-клиента. Файлы буферизуются в памяти.

## Сессия и проверка

Сессия по-прежнему хранится в localStorage под прежним ключом для совместимости. HTTP-клиент добавляет Bearer и выполняет refresh при 401. Не помещать секреты в VITE-переменные. API по умолчанию localhost:7170; VITE_API_BASE_URL переопределяет адрес.

`npm run lint`, `npm run build`, `npm test`. Контрактные тесты используют два customer fixture из соседнего Corelia: проверяют рендерер схем, типы значений и сохранение concurrency metadata. `node tests/ui-preview.mjs customer-a` либо customer-b запускает изолированную UI-имитацию на 127.0.0.1:7178. Она не проверяет настоящую авторизацию, BPM, DAM, транзакции или GraphQL и не является полноценным acceptance стенда.
